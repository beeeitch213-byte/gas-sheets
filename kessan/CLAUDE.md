### 予約の指示文とこのファイルをそろえる

- 予約(scheduled tasks)はこのファイルを自動では読まない。このファイルの取り決めを変えても、予約の指示文は変わらない。
- **予約の指示文と、このファイルの取り決めは、変えるときにかならず両方そろえる。** 片方だけ変えない。
  - このチャットに届く予約(毎朝・カレンダー画像)は、指示文で「kessan/CLAUDE.md に従う」と書いているので、このファイルの手順を変えれば届いたときに反映される。指示文そのものを変えるときは、上の「予約の指示文」も書き直す。
  - 新しいセッションで動く予約(決算スケジュール作成)と、毎朝作る評価の予約は、手順を指示文に直接書いている。このファイルの該当する取り決め(「評価の指示文」「評価セッションの流れ」「SBI からの取得」など)を変えたら、指示文も合わせて変える。
- 予約の動きを変える変更(このファイルの手順の変更を含む)は、マージや予約の更新の前にマスターに一言確認する(ルートの `CLAUDE.md` の「デプロイ」)。

- 旧ルーティン「決算評価(発表当日)」(16:47/19:47 に TDnet を見る方式)は削除済み。
- 予約で動いたセッションは通常のセッション一覧に出ない。リンク(`https://claude.ai/code/session_…`)から開く。
- 予約を削除すると、その予約で動いたセッションも消える。評価の全文が入った予約は消さない。

## 毎朝 8:43「今日の決算評価を予約して」が届いたら

1. 「決算情報取得銘柄」シートを読む。読めなければ理由を書いて終了。
2. SBI 証券の決算発表スケジュールで、今日発表する対象銘柄と予定時刻を調べる(取り方は下の「SBI からの取得」)。会社の IR ページや適時開示の予告で今年の時刻が分かればそちらを優先する。
3. 評価の予約を作る(`create_trigger`、`run_once_at`、`create_new_session_on_fire: true`、`notifications: {push: true}`)。
   - 開始は予定時刻の **2分前**(セッションの起動に1〜2分かかる)。
   - 同じ時刻の銘柄は1つの予約にまとめる。
   - 時刻が「--」(未定)の銘柄は 16:00 と 19:30 の2回入れる。2回目は、1回目で評価済みなら何もしない。
   - プロンプトには銘柄コード・銘柄名を直接書き、下の「評価の指示文」を使う。
4. 評価の約15分後に、このチャット宛ての結果確認(`send_later`)を入れる。
5. 発表が無い日は「本日の対象なし」とだけ書いて終了。
6. 作った予約(時刻・銘柄・trigger_id)を一覧で書く。

## 評価セッションの流れ

| タイミング | やること |
|---|---|
| 予定時刻の2分前 | セッション開始 |
| 予定時刻から | TDnet の一覧 `https://www.release.tdnet.info/inbs/I_list_001_YYYYMMDD.html`(今日の1ページ目)を **3秒ごと**に取得し、対象コード(末尾に0が付いた5桁、例: `285A0`)かつ表題に「決算短信」を含む行を探す。最長60分で打ち切り、見つからなければ「開示を確認できず」と通知する |
| 見つけたらすぐ | 決算短信 PDF の1ページ目(サマリー)だけを読み、**速報**を PushNotification で送る |
| その2〜3分後 | 株価・コンセンサスも調べて全文評価(A〜D)。**評価**を PushNotification で送る |
| 最後 | 最後の返答に A〜D の全文を書く(「通知しました」だけで終えない) |

- 速報の形: `【決算速報 ○/○】銘柄名(コード) 売上 ○○億円(+○%) 営業益 ○○億円(+○%) 予想:修正なし/上方/下方/非開示 配当:○○円`
- 評価通知の形: `【決算評価 ○/○】銘柄名(コード) ◎/○/△ … (理由を短く)`
- 通知は200文字以内。PushNotification は `ToolSearch` の `select:PushNotification` で読み込んでから使う。
- 評価セッションからこのチャットへは `send_message` できない(ツールが無い)。結果はこのチャット側から見に行く。
- 2026/11/01 のテスト(キオクシアHD)では、開示の発見から速報まで約4秒、評価まで約21秒だった。ただし速すぎて株価・コンセンサスを調べていなかったので、本番では調べてから評価する。

## 根拠についての決まり(すべての回答に適用)
- すべての主張と数値に、明確な根拠(決算短信・決算説明資料・有価証券報告書・JPX・会社のIRページなど)を付ける。数値には出典(資料名・発表日・該当する表の名前)を添える。
- データが見つからない・確認できない項目は、推測で埋めずに「データ不足」と書く。
- 推測や解釈を書くときは「(推測)」「(解釈)」と明記し、事実と分ける。
- 結論を出す前に、多角的な視点からメリット・デメリットを整理する。
- 売買の推奨はしない(最終判断は私がする)。

## 評価の形式(銘柄ごと)
【A. 結果の要約】
1. 結果: 売上高・営業利益・経常利益・純利益(前年同期比 %)
2. 会社予想に対する進捗率(通期予想に対して。前年同期の進捗率とも比べる)
3. 通期予想の修正の有無と内容(上方/下方/据え置き。修正幅も)
4. 配当(予想・修正の有無)

【B. 調査分析項目】(項目ごとに 数値 / 前年同期・前期末との比較 / 出典 を書く)
1. 売上高・各利益の前年同期比(YoY)と進捗率
2. 売上高営業利益率(マージン)の水準と前年同期からの変化
3. 営業キャッシュフロー(四半期の開示が無ければ「データ不足」)
4. コンセンサス(市場予想)との乖離。出典を明記し、見つからなければ「データ不足」
5. 業績予想の修正(上方修正・下方修正)と、会社が説明している理由
6. 株主還元(増配・減配、自社株買いの有無と規模)
7. 受注残高・受注状況(開示が無い業種・会社は「開示なし」)
8. 売上債権と棚卸資産(在庫)の前期末からの増減と、売上の伸びとの比較
9. 自己資本比率とネットキャッシュ(現金同等物 − 有利子負債)
10. PER と PBR(使った株価と日付を明記。予想EPS・BPSの出典も)

【C. 評価】
5. ポイント: 良かった点・悪かった点を3つずつまで(それぞれ根拠となるB.の項目番号を付ける)
6. 総合評価: ◎良い / ○普通 / △悪い と、その理由を2〜3行(結論の前に、メリット・デメリットを整理した表を置く)

【D. 出典一覧】使った資料をすべて挙げる(資料名・発表日・URL)。

## 結果確認(このチャットに書く形)

1. 1行目: `【決算評価 ○/○】銘柄名(コード) ◎/○/△ …`
2. 銘柄ごとの **C. 評価**(良かった点・悪かった点、メリット・デメリットの表、総合評価と理由)。銘柄が多い日は ◎→○→△ の順。
3. 全文(A〜D)を開くための評価セッションのリンク。
4. 終わっていない・失敗していたら、その状態。

評価セッションの session_id は、評価の予約の `last_run.session_id`(`get_trigger`)で分かる。`cse_…` を `session_…` に読み替えてリンクにする。

## SBI からの取得(発表日・予定時刻)

- SBI 証券の決算発表スケジュール(国内株式)のページはデータを後から読み込むので、WebFetch では中身が取れない。データの配信元を直接読む。
- 手順:
  1. ページ `https://www.sbisec.co.jp/ETGate/?_ControlID=WPLETmgR001Control&_PageID=WPLETmgR001Mdtl20&_DataStoreID=DSWPLETmgR001Control&_ActionID=DefaultAID&burl=iris_economicCalendar&cat1=market&cat2=economicCalender&dir=tl1-cal%7Ctl2-schedule%7Ctl3-stock%7Ctl4-calsel&file=index.html&getFlg=on` を取得し、`ANNOUNCE_INFO_PARAM = '?hash=…&type=delay'` を抜き出す(hash は毎回取り直す)。
  2. 銘柄ごとに `https://vc.iris.sbisec.co.jp/calendar/settlement/stock/announcement_info_stock.do{PARAM}&productCode={コード}&inputWord=&callback=cb` を取得する(文字コードは Shift_JIS、JSONP)。
  3. `date`(発表日)、`time`(予定時刻)、`publishStatus`(予定/発表済)、`type`(決算期)を読む。
- 予定時刻は「前年同期に TDnet で決算短信が出た時刻」。今年の時刻とずれることがある。
- 時刻が `--` の銘柄は未定として扱う。日付が「11月中旬」のように未確定のものもある。

## 決算カレンダー画像

- 毎月28日 18:17 に来月分を作ってこのチャットに送る(`SendUserFile`)。銘柄リストを更新したときも作り直す。
- レイアウト:
  - 月曜始まり。土日の列は日付が入る最小幅、月〜金の列を広くする。

  - 下の注意書きはその月に関係するものだけ(日付が未確定の銘柄、時刻が未定の銘柄など)。
- 作り方: HTML を作って Playwright でスクリーンショットを撮る(日本語フォントは IPAPGothic)。

## 通知について

- スマホと PC(Chrome)に届く。claude.ai をスマホや PC で開いていると、スマホへの通知が省かれることがある。
- iPhone のバナーは「一時的」だと数秒で消える。残したいときは 設定 → 通知 → Claude → バナースタイル →「持続的」。
- 通知の全文は評価セッションに残る。
